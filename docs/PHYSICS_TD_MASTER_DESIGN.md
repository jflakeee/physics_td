# Physics TD — 통합 설계·조사·구현 자료집

> 기준: 2026-11-07. 이 문서는 확인된 프로젝트 대화와 GitHub 소스의 내용을 재구성한 문서다. 외부 원본이 확인되지 않은 자료는 확인된 것처럼 기재하지 않는다.

## 1. 프로젝트 목표 및 범위
- 장르: 물리 기반 자연재해 방어 시뮬레이션/타워디펜스.
- 핵심 재미: 적 유닛 처치가 아니라 **자연 현상(홍수, 범람, 결빙·융해)에 대응하여 중앙 기지를 보호**하는 전략.
- 플랫폼: 모바일 우선 브라우저 게임, GitHub Pages 배포. Android 빌드/배포는 현재 범위에서 제외.
- 뷰: 초기 사이드뷰(100×60 격자)에서 탑뷰(40×24 격자)로 전환.
- 다방향 위협: 북·남·동·서 네 유입구에서 동시에 물이 들어오는 구조.

## 3. 설계 변천과 결정
1. **사이드뷰 원형:** 높이별 지면, 물 흐름, 냉각탑과 얼음, 방벽 설치.
2. **적 처치형 확장:** 적 유닛 체력, 경로 탐색, 공격 포탑, 처치 보상, 웨이브 통계 추가. 자연재해 중심 기획과 충돌.
3. **UX 개선:** 클릭/터치로 좌표 고정, 방향 버튼·키보드 이동, 확정/취소, 설치 가능 여부 안내, 모바일 UI 개선.
4. **탑뷰 v5.0:** 중앙 기지와 동서남북 침투구. 처음에는 4방향 적 유닛을 생성.
5. **자연재해 복원 v5.1:** 적 생성/공격을 제거하고 네 유입구의 홍수, 배수펌프, 침수 피해로 전환.

**최종 방향:** 탑뷰를 유지하고 위협은 물리적 자연 현상으로만 표현한다. 기존 `enemies`, `kills`, `leaks`, `tower` 등의 레거시 내부 명칭은 의미가 혼재되어 단계적으로 정리한다.

## 4. 현재 게임 규칙 (코드 기준)
- 격자: 40×24, 중앙 기지 (20,12).
- 유입구: 서(1,12), 동(38,12), 북(20,1), 남(20,22).
- 재해 단계: 총 5개. 단계가 높아질수록 물 유입량과 빈도가 증가.
- 유입: 각 유입구에 동일 틱에 물을 추가. 한 셀의 물·얼음 용량은 최대 1을 기준으로 제한.
- 이동: 인접 4방향 셀의 물 수위 차를 이용한 단순 확산 모델. 실제 유체역학 CFD, 지형 고도, 수압 모델은 아직 없음.
- 결빙: 냉각탑 주변 물을 얼음으로 전환; 얼음은 서서히 녹음.
- 배수: 배수펌프 주변의 물을 매 틱 감소시킴.
- 피해: 기지 주변 3×3 셀의 물 합계가 임계값 1.2 이상이면 틱당 기지 체력 1 감소.
- 초기 체력 100, 자금 150. 단계 완료 시 자금 보너스 20.
- 제방 설치 15, 배수펌프 35, 냉각탑 45. 기지/유입구 보호 영역과 이미 점유된 셀은 설치 불가.
- 현재 화면의 일부 통계 라벨은 적 처치형 시스템에서 남은 명칭으로, 재설계가 필요함.

## 5. 플레이 흐름
1. 재해 예고(강도, 유입 주기)를 확인.
2. 탑뷰 격자에서 시설을 선택하고 위치를 클릭/터치하여 고정.
3. 방향 버튼 또는 방향키로 한 칸씩 이동.
4. 설치 가능 여부, 비용을 확인하고 설치 확정.
5. 웨이브를 시작해 유입·확산·결빙·배수 상태를 관찰.
6. 기지 침수 피해를 최소화하며 다섯 재해를 방어.
7. 결과를 확인하고 시설을 재배치하거나 재도전.

## 6. 주요 UX 요구사항
- 모바일 터치 우선; 44px 이상 주요 터치 대상.
- 위치를 누른 뒤 드래그하거나 손을 떼도 선택 좌표 유지.
- 좌표 미세 조정, 설치 확정/취소 분리.
- 배치 불가 이유와 비용 안내.
- 일시정지/재도전/초기화.
- FPS 및 스텝 처리 시간 확인.
- 접근성: 버튼 레이블, 대비, 상태 메시지, 키보드 조작.

## 7. 검증 및 알려진 위험
- `npm test`, `npm run build`, `node --check src.js`로 CI 검증.
- 구형 `engine.js` 테스트는 레거시 동작을 확인하며 새 홍수 엔진의 정합성을 대체하지 못함.
- 새 `tests/topview.test.js`는 사방 유입, 기지 침수, 시설 설치 등을 확인.
- 최근 자연재해 전환 중 UI 문법 오류로 GitHub Actions 실패 이력이 있음. 수정 후 최신 워크플로 결과를 반드시 확인해야 함.
- 탑뷰 엔진에 사용하지 않는 적 유닛 필드·경로 탐색 함수가 남아 있음.
- '물길 보기'는 과거 적 이동 경로를 기반으로 하여 실제 수류 방향 표시 기능으로 재설계 필요.
- 물의 보존·펌프 제거량·빙결/융해, 장시간 실행, 모바일 FPS, 터치 이벤트 전체 흐름에 대한 회귀 검증을 강화해야 함.
- 물의 확산은 단순 격자 모델이므로 실제 수압/고저차 재현이라고 표현하면 안 됨.

## 8. 미구현 상세 설계 — 우선순위
### P0: 정확성·배포
- CI 전부 통과, Pages 배포 성공 검증, 브라우저 실기동 확인.
- UI 잔존 적 관련 문구/통계 제거 및 자연재해 용어로 통일.
- 모든 재해 단계의 승패·재도전·일시정지 테스트.

### P1: 자연재해 플레이 완성
- 지형 고도(높이 맵) 및 수위에 따른 흐름.
- 제방 내구도, 누수, 범람, 파괴.
- 배수펌프의 처리량/전력/배출 방향.
- 강우, 상류 범람, 해일 등 유입 원인별 패턴.
- 물의 흐름 방향·속도·침수 위험 시각화.
- 재해 종료 후 잔류 수량 및 복구 비용 밸런스.

### P2: 확장
- 쿼터뷰 렌더링 비교(조작 정확도·가독성 검증 후 결정).
- 시설 업그레이드와 비용 밸런스.
- 미션/지도/난이도 및 재해 이벤트 조합.
- 게임 저장·불러오기 및 모바일 성능 최적화.
