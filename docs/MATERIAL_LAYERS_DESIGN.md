# 물질 층 시스템 설계 (Material Layers) — v0.1 초안

> 상태: **설계 초안 (출시 후 지역 확장용).** MVP(홍수 + 빙하)는 이 문서의 영향을 받지 않는다.
> 근거: 현재 엔진(`src/sim/`, 64×96 격자, 30 tick/s, 2패스 가상 파이프 K=0.20)과 성능 실측
> (sim step 데스크톱 ≈0.24ms, 4× CPU 스로틀 평균 ≈1.1ms, 기준 < 2.0ms).
> 관련 문서: `GAME_DESIGN_V2.md`(규칙), `DETAILED_DESIGN_V2.md`(구현), `STORY_WORLD_EXPANSION.md`(지역·세계관).
> 미결정 항목은 사용자 지시("미결정은 권장항목으로 진행")에 따라 **권장안을 채택**했고 §13에 모았다.

## 1. 목적과 범위

물 외에 **기름·용암·모래(자갈·진흙)·눈사태·플라즈마장**을 같은 엔진 위에서 다룬다.
지역 확장(빙하·화산·산사태·심해·외계/기계, `STORY_WORLD_EXPANSION.md`)마다 "이 지역의 위협은 어떤 물질인가"를
데이터로 정의할 수 있게 하는 것이 목표다.

- 포함: 물질 데이터 스키마, 층 구조, 갱신 규칙, 반응표, 수단 상성, 피해, 성능 예산, 검증 계획.
- 제외: 개별 강체(굴러오는 바위 한 덩이)의 물리, 3D·옆면 시점 입자 시뮬(Noita식), 연기·불꽃 같은 순수 연출 파티클.
- 위협은 **현상으로만** 표현한다(적 유닛 없음 — 기존 원칙 유지). 외계·기계 위협도 플라즈마장·기름 같은 현상으로 그린다.

## 2. 설계 원칙

1. **층 + 규칙.** 물질마다 코드를 쓰지 않고, 물질 종류(kind) 몇 개의 갱신 규칙 + JSON 파라미터로 정의한다.
2. **맵당 특수 물질 최대 2종.** 물(기본 층)은 별도이고, 특수 물질은 맵 데이터가 선언한 것만 갱신한다(성능과 가독성).
3. **결정성.** 같은 시드·같은 입력이면 같은 결과(같은 기기·같은 빌드). `Math.random`·`Math.sin` 금지, 난수는 기존 3스트림 중 `weather`/`events` 외에 **`material` 스트림을 추가**한다.
4. **보존.** 층마다 질량(부피)이 보존된다. 물질 사이 변환은 데이터의 고정 비율로만 일어나며, 소실분(증기 등)은 `lost[materialId]` 카운터에 기록한다.
5. **수단 상성이 깊이.** 펌프·제방·결빙·수문·모래주머니가 물질마다 다르게 먹혀야 한다(§8). 단일 수단은 지고 혼합은 이기는 봇 기준(스토리 004)을 새 물질에도 적용한다.
6. **데이터 중심.** 점성·밀도·안식각·반응표·피해 가중치는 전부 `data/materials/*.json`. 코드에 게임 숫자 리터럴 금지.

## 3. 물질 종류(kind)와 최소 갱신 규칙

| kind | 설명 | 갱신 규칙 | 예 |
|---|---|---|---|
| `liquid` | 수두 차로 흐르는 액체 | 2패스 가상 파이프(기존 `fluid.ts`를 층별로 일반화) | 물, 기름, 용암, 진흙 |
| `granular` | 기울기가 안식각을 넘으면 흘러내림 | 2패스 안식각 이동(§5.3) | 모래, 자갈, 눈 |
| `field` | 질량 보존이 없는 확산·감쇠 장 | 이웃 평균 확산 + 감쇠 | 플라즈마장 |

개별 물체(굴러오는 바위)는 만들지 않는다. **바위는 두 가지로만 표현한다.**
(a) 산사태 잔해 = `granular` 층 (자갈), (b) 용암이 식어 굳은 결과 = 지형 높이 증가.

## 4. 데이터 스키마 (`data/materials/*.json`)

```json
{
  "id": "lava",
  "kind": "liquid",
  "density": 2.4,
  "flowK": 0.04,
  "updateEvery": 3,
  "heat": { "initial": 1.0, "coolPerSec": 0.02, "solidifyBelow": 0.25, "solidifyScale": 0.8 },
  "damage": { "baseWeight": 3.0, "levee": 0.05, "ice": 4.0 },
  "colors": ["#ff7a1a", "#c0392b", "#2b1a16"]
}
```

| 필드 | 의미 | 비고 |
|---|---|---|
| `kind` | `liquid` / `granular` / `field` | 규칙 선택 |
| `density` | 층 쌓임 순서(큰 것이 아래) | 물 = 1.0 기준 |
| `flowK` | 액체 흐름 계수(물 0.20) | 안정 조건 ≤ 0.25 유지 |
| `repose` | (granular) 안식각 = 셀 간 허용 높이차 | |
| `rate` | (granular) 틱당 이동 비율 | |
| `updateEvery` | N tick마다 갱신(느린 물질 비용 절감) | 흐름 계수는 N배로 보정 |
| `heat` | (용암) 열 필드 초기값·냉각률·굳음 임계·굳음 시 지형 증가 비율 | |
| `damage` | 기지 피해 가중치, 구조물(제방 내구도·얼음 융해)에 대한 가중치 | §7 |
| `diffuse`, `decayPerSec` | (field) 확산·감쇠 | |

반응표는 `data/materials/reactions.json`에 둔다(§6). 맵은 `materials: ["lava", "sand"]`로 쓰일 물질을 선언한다.

## 5. 층 구조와 갱신 규칙

### 5.1 층

```
ground h[i]      지형 + 구조물(제방·얼음) 높이   (기존)
w[i]             물 깊이 (Float64, 기존)
m_k[i]           특수 물질 k의 깊이 (Float32, 맵이 선언한 최대 2개)
heat[i]          (용암 사용 시) 셀 열량 0..1 (Float32)
f_k[i]           (field 사용 시) 장 강도 (Float32)
```

- 정밀도: 물만 Float64(질량 보존 1e-4 기준이 걸려 있음, 스토리 001). 특수 층은 Float32이며 보존 허용 오차는 **층별 1e-3**.
- 층별 활성 셀 목록(깊이 > ε인 셀과 그 이웃)만 갱신한다 → 대부분의 칸이 비어 있는 맵에서 비용이 작아진다.

### 5.2 액체 일반화 (물·기름·용암·진흙)

수두는 **자기 아래에 깔리는 층의 깊이**를 포함한다. 밀도가 큰 물질이 아래에 쌓인다.

```
head_m[i] = h[i] + Σ(자기보다 밀도 큰 층의 깊이) + depth_m[i]
flux_m(i→j) = flowK_m × (head_m[i] − head_m[j])   (0 이상, 두 패스, 순서 무관)
```

- 용암(밀도 큰 층)은 물의 "바닥"이 되고, 기름(밀도 작은 층)은 물 위에 뜬다.
- 점성은 `flowK`로 표현한다(용암 0.04 ≈ 물의 1/5). `updateEvery: 3`이면 3 tick마다 한 번 `flowK×3`(상한 0.25)로 계산해 비용을 1/3로 줄인다.
- 제방·얼음·수문이 막는 방식은 기존과 같다(수두에 높이로 포함). 단 `damage.levee`로 내구도 마모가 물질마다 다르다(용암 = 제방 녹임).

### 5.3 입자 이동 (모래·자갈·눈)

```
diff = (h[i] + m[i]) − (h[j] + m[j])
if diff > repose:  move(i→j) = min(m[i], (diff − repose) × rate / 2)   (두 패스, 순서 무관)
```

- 물이 많이 닿은 모래 셀은 **진흙**으로 취급한다: `w[i]/m[i] ≥ mudRatio`이면 그 셀의 입자 이동은 액체 규칙(`flowK_mud`)을 쓴다. 마르면 원래대로 돌아온다.
- **눈사태** = 눈 층의 입자 이동 + 촉발 조건: 한 셀의 눈 깊이가 `avalancheDepth`를 넘고 이웃과의 높이차가 `repose`의 `triggerMul`배를 넘을 때, 그 칸 주변이 한 틱에 한꺼번에 무너진다(연쇄는 빙하호 붕괴 규칙과 같은 방식으로 같은 틱에 처리). 눈은 `meltPerSec`로 녹아 물이 된다(질량 변환, 반응표 `snow→water`).

### 5.4 장 (플라즈마)

```
f[i] += diffuse × (평균(이웃 f) − f[i]) ;  f[i] *= (1 − decayPerSec/30)
```

- 질량 보존 없음. 원천(맵 데이터의 `emitters`)에서 틱마다 주입.
- 효과: 제방 내구도 감소, 기름 점화, 펌프 일시 정지, 얼음 융해(§6). 물과 만나면 증기로 소실.

## 6. 반응표 (`reactions.json`)

반응은 같은 셀에 두 물질이 함께 있을 때, 틱당 `rate` 비율로 일어난다. 모든 변환은 고정 비율이다.

| 입력 | 결과 | 비고 |
|---|---|---|
| 용암 + 물 | 용암 일부 굳음(지형 +`solidifyScale`×깊이), 물 일부 **증기**(소실, `lost.water`) | 식히는 수단이 됨 |
| 용암 + 얼음 | 얼음 융해(빙하호 붕괴 규칙과 같은 처리), 용암 열 감소 | 빙하 × 화산 지역 연결 |
| 용암 + 기름 | 기름 점화(불 상태: 기름 깊이 감소 + 열 증가) | |
| 기름 + 플라즈마장 | 점화 | |
| 모래 + 물 | 진흙 셀(§5.3) | 질량 보존 |
| 눈 + (열 또는 시간) | 눈 → 물 | `meltPerSec` |
| 용암 + 모래 | 모래가 유리/굳은 지형으로 | 선택(후순위) |

## 7. 피해

기지 피해(스토리 001 규칙 일반화): 기지 3×3 합계를 물질별 가중치로 환산한다.

```
flood = Σ_m  weight_m × (기지 3×3의 depth_m 합)
HP 손실 = max(0, flood − 1.2) × 2 / 30   (틱당, HP는 정수 + 소수부 누적 — 기존과 동일)
```

- `weight_water = 1.0`. 용암·기름·진흙은 데이터로 더 크게 줄 수 있다(예: 용암 3.0).
- 구조물 피해: 제방 내구도 마모 = 기존 `0.012 × 압력/s` + 물질별 `damage.levee × 깊이`. 얼음은 `damage.ice` 배율로 녹는다.

## 8. 수단 상성

| 수단 | 물 | 기름 | 용암 | 모래·진흙 | 눈사태 | 플라즈마장 |
|---|---|---|---|---|---|---|
| 제방 | 기본 | 기름은 물 위로 넘치기 쉬움(높이 필요) | 녹음 → **얼음·바위 둑 필요** | 쌓임으로 일부 막힘 | 약함(무너져 넘침) | 막지 못함 |
| 펌프 | 기본 | 효율 낮음(점성) | 불가 | 불가(진흙만 일부) | 불가 | 일시 정지됨 |
| 결빙 | 기본 | 효과 없음 | **식혀 굳힘(핵심 대응)** | — | 눈을 단단히 고정(붕괴 억제) | — |
| 수문 | 기본 | 가능 | 열기 전엔 막지만 녹음 | 가능 | — | — |
| 모래주머니 | 기본 | 약함 | 즉시 타 버림 | 가능 | 가능(눈 흡수) | — |
| 새 수단(후보) | — | 흡착포 | 냉각수 | 굴착 | 인공 눈사태(미리 무너뜨리기) | 접지(장 소산) |

이 표가 "물질이 바뀌면 정답 수단이 바뀐다"를 만든다. 스토리 004의 봇 검증처럼 **지역마다 단일 수단은 패배, 혼합은 클리어**를 보장한다.

## 9. 성능 예산

기준: 물 + 방어 sim ≈ 0.24ms(데스크톱) / ≈ 1.1ms(4× 스로틀 평균, p99 ≈ 2.0ms). 한도 2.0ms(4×).
층 하나를 전체 해상도로 매 tick 돌리면 대략 데스크톱 +0.1~0.2ms, 4× +0.5~1ms(추정, 프로토타입에서 확정).

| 대책 | 효과 |
|---|---|
| 활성 셀 목록(깊이 > ε인 셀과 이웃만) | 빈 맵 대부분에서 층 비용 거의 0 |
| `updateEvery` (용암·모래 3 tick) | 해당 층 비용 1/3 |
| Float32 특수 층 | 메모리·캐시 절반 |
| 맵당 특수 물질 최대 2종 | 최악 비용 상한 고정 |
| 반응은 접촉 셀 목록에서만 | 전체 스캔 없음 |

**수용 기준:** 물 + 특수 2종이 활성인 최악 시나리오에서 4× 스로틀 평균 < 2.0ms, p99는 참고(스토리 001 AC9와 동일 방식으로 측정).
넘으면 순서대로 `updateEvery` 증가 → 활성 영역 제한 → 해상도(특수 층만 절반 해상도) 순으로 줄인다.

## 10. 지역 ↔ 물질 매핑

| 지역(세계관) | 특수 물질 | 핵심 상호작용 |
|---|---|---|
| 강 유역 | 없음 (물) | 기본 규칙 |
| 빙하시대 | 얼음(기존) + **눈사태**(눈 층) | 눈사태 → 녹은 물 → 빙하호 붕괴 연계 |
| 화산 | **용암** (+증기) | 결빙·물로 식혀 굳힘, 제방은 녹음 |
| 산사태 | **모래·자갈·진흙** | 흙더미가 물길을 막았다 터짐 |
| 심해 | 물 (수압·조류: `flowBias`) | 물질 추가 없음, 흐름 편향 |
| 외계·기계 | **플라즈마장**, 기름 | 현상으로만(적 유닛 없음), 점화·펌프 정지 |

## 11. 검증 계획

1. **프로토타입** `prototypes/material-layers-check.mjs`: 물 + 용암 + 모래를 `src/sim`의 격자 위에 얹어 (a) 층별 질량 보존, (b) 대칭성, (c) 결정성(같은 시드 해시), (d) 4× 스로틀 성능을 잰다. 통과 못 하면 §9 대책 순서대로 줄인다.
2. **수용 기준(프로토타입 단계)**
   - 층별 질량 변화: 반응 없는 1만 tick에서 물 < 1e-4, 특수 층 < 1e-3.
   - 좌우 대칭 지형에서 대칭 셀 차 < 1e-6(물), < 1e-4(특수 층).
   - 같은 시드 → 같은 해시(같은 기기·같은 빌드).
   - 10만 tick 랜덤 지형에서 NaN·음수 없음.
   - 4× 스로틀 평균 < 2.0ms(물 + 특수 2종).
3. **게임 단계:** 지역 맵마다 스토리 004와 같은 봇 7전략(단일 수단 전부 패배, 혼합 클리어)을 새 수단 상성에 맞게 확장.

## 12. 구현 단계 (출시 후, 스토리 후보)

| 단계 | 내용 | 선행 |
|---|---|---|

## 15. M0 결과 (2026-11-19)

`node prototypes/material-layers-check.mjs` — 물 + 용암 + 모래를 실제 `src/sim` 격자(둑마을) 위에 얹어 §11-1을 검증. 코드: `prototypes/material-layers/`(버리는 프로토타입, M1에서 `src/sim`으로 새로 구현).

| 검사 | 기준 | 결과 |
|---|---|---|
| (a) 질량 1만 tick | 물 < 1e-4, 특수 층 < 1e-3 | 물 1.6e-12, 용암 2.4e-4, 모래 3.1e-4 — **통과** |
| (b) 좌우 대칭 | 물 < 1e-6, 특수 층 < 1e-4 | 전부 0 (비트 일치) — **통과** |
| (c) 결정성 | 같은 시드 → 같은 해시 | 같음, 다른 시드는 다름 — **통과** |
| (d) 10만 tick 랜덤 지형 + 원천 + 반응 | NaN·음수 없음 | 없음 (증기 366, 굳은 용암 2967) — **통과** |
| (e) 4× 스로틀 평균, 추적기 끔 | < 2.0ms | 1.55ms (물만 1.16, 층 +0.39) — **통과** |
| (e) 4× 스로틀 평균, 추적기 켬(플레이 화면) | < 2.0ms | 2.23ms (물만 1.76, 층 +0.47) — **실패** |

- 최악 시나리오: 둑마을 W5 + 제방 링 + 펌프 2대 + 용암(북쪽 1/3)·모래(남쪽 1/3) 활성, 30 tick마다 용암·모래 원천 주입, 반응 켬. 실행마다 ±0.2ms 흔들림.
- **판정: 정확성 통과, 성능은 조건부.** 층 비용(+0.4~0.5ms)보다 **출처 추적기(+0.6ms)**가 예산을 먼저 씀 — 물만으로도 추적기를 켜면 1.76~2.02ms. M1 전에 (1) 추적기 최적화 또는 특수 물질 맵에서 추적기를 2 tick마다 실행, (2) 그래도 넘으면 §9 순서(갱신 주기 4 → 활성 영역 제한 → 특수 층 절반 해상도)를 적용.
- M0에서 확정한 구현 사항(M1 반영):
  - 층 갱신은 함수 콜백 대신 인라인 계산(추가 비용 0.47 → 0.24ms, 엇갈림 포함).
  - 같은 `updateEvery`의 층은 tick을 **엇갈려** 갱신(`(tick + k) % N`) — p95 튐 4.6 → 3.4ms.
  - 용암 열은 **에너지(= 열 × 깊이)**로 저장해 흐름과 같은 비율로 함께 옮김. 셀 속성으로 두면 흘러간 칸이 즉시 굳음.
  - 특수 층이 물 아래 "바닥"이 되는 처리는 물 스텝 동안 `h`에 층 깊이를 더하고 끝나면 저장해 둔 `h`로 비트 단위 복원.
  - 특수 층 Float32의 질량 오차는 1만 tick에 2~4e-4로 기준(1e-3) 안. 판 길이(약 8,000 tick)에서는 충분.
