## 2. 🔴 치명

### C1. 기지가 고지대라 물이 닿지 않는다
**근거 (시뮬레이션, 방어 없음)**

| 조건 | 결과 |
|---|---|
| 설계 수치 그대로 (I1=18) | W5까지 기지 최대 수위 **0.000**, HP 100 |
| 유입 10배 (I1=200, 증발 0) | 기지 최대 수위 **0.000**, HP 100 |
| 기지 높이를 평지와 같게 + I1=60 | W5 기지 수위 0.756 (임계 1.2 미달) |

- 원인: 타일 기본 높이에서 기지 `B=1.4`가 평지 `P=1.0`보다 높다. 기지를 침수시키려면 평지 약 4,500셀을 0.4 이상 채워야 함(≈1,800 단위) → 5웨이브 총 유입(≈180)의 10배.
- **수정**: **집수 분지 원칙** — 기지는 맵에서 가장 낮은 지대에 둔다. 지면고 = `기지 수위 기준 0.6 + 0.8 × (기지로부터 정규화 거리)` + 타입 보정. 유입구 → 기지로 경사.
- 검증: 이 경사 + I1=100에서 방어 없이 **W4 패배**(목표 W2~W3에 근접, I1 ≈ 130에서 W3 예상).

### C2. 증발이 유입량의 약 100배
- 설계: 모든 젖은 셀에서 tick당 `0.0002` 고정 제거. 물이 얇게 퍼지면 6,144셀 × 0.0002 × 30 = **초당 약 37 단위 소멸**. W1 유입은 초당 0.3.
- 시뮬레이션: I1=18에서 웨이브 종료 시 남은 물 1.0~3.8 (유입분 거의 전부 증발).
- **수정**: 수심 비례 `e = w × 0.00002` (얕게 퍼진 물은 거의 안 줄고, 웨이브 간 누적 관리가 의미를 가짐). 또는 증발 제거.

### C3. 구역 자동 생성이 "평지 한 덩어리"가 된다
- 설계: 같은 타입 타일의 4연결 덩어리 = 구역. 실측: **둑마을 평지 구역 1개가 96타일 중 86타일**, 버드나무 들 평지 70타일이 한 구역.
- 결과: 평지 어디를 눌러도 같은 구역 → 제방 쌓기 대상 구분 불가, 제방선이 맵 외곽이 됨. "구역 탭" 조작 체계 전체가 무너짐.
- **수정**: 구역을 **타입과 분리된 별도 레이어**로 저작.
  ```json
  "zones": ["aabbbbcc", "aabbbbcc", ...]   // 12줄 × 8자, 같은 문자 = 같은 구역
  ```
  - 저작 규칙: 구역 6~12개, 구역당 4~16타일, 각 유입구 → 기지 경로가 2개 이상의 구역을 지나도록.
  - 자동 기본값(저작 생략 시): 기지 중심 **8방위 × 2링(안/밖) = 16 섹터**를 타입 경계로 자름.

### C4. 무피해 점수가 판당 3,375점 → 성장 곡선 붕괴
- 설계: 무피해 10 tick마다 +3. 웨이브 합계 11,250 tick → 무피해면 **3,375점**. 플레이 점수 목표(1,100~1,300)의 약 3배, 경험치로 환산하면 Lv12 이상.
- 또한 "무피해"는 모든 방식의 공통 목표라 방어 방식만의 점수원이 아님.
- **수정**: 무피해 점수를 **웨이브 단위 +60**(그 웨이브 피해 0일 때)으로 변경, 그리고 점수원별 **경험치 예산표**를 확정해 합이 목표에 맞는지 검증:

  | 점수원 | 판당 목표 기여 |
  |---|---|
  | 웨이브 클리어 (W1~W4) | 400 |
  | 무피해 웨이브 | 0~300 |
  | 방식 고유 (차단·생태·자재·저류) | 300~450 |
  | 배수량 | 100~200 |
  | **합계** | **≈ 1,100~1,300** |
  - 방식 고유 점수원의 계수는 이 예산에 맞춰 봇으로 역산.

### C5. 펌프 1대로 이기는 지배 전략이 재발
- 시뮬레이션 (경사 지형, I1=100, 기지 북쪽 경로 위 펌프 1대 상시 가동):

  | 펌프 출력 | 결과 |
  |---|---|
  | 없음 | W4 패배 |
  | 설계값 0.015/셀 | **HP 100 클리어** |
  | 1/3 출력 0.005/셀 | **HP 91 클리어** |
- 출력이 아니라 **물이 지나가는 길목**이 문제. 출력을 줄여도 효과가 크게 줄지 않는다. v1 리뷰의 "펌프가 정답" 문제가 그대로 남음.
- **수정**
  1. **펌프 1대 총 처리량 상한**: tick당 합계 ≤ `맵 W3 평균 유입 속도 × 25%` (맵 데이터에서 자동 계산).
  2. 펌프 거점은 **주 경로에서 벗어난 곳**에 둔다(맵 설계 가이드, M10).
  3. 동시 가동 수 제한(전력): 맵당 2대.

### C6. 물 "단위"가 정의되지 않아 높이 수치가 서로 안 맞는다
- 실측 수심: 기지가 침수될 때 셀당 수심 약 0.13~0.2 (flood 1.2~1.7 / 9셀).
- 그런데 제방 높이 1.0~1.6, 모래주머니 0.8, 수문 2.0, 들판 수입 조건 수위 0.3, 숲 피해 수위 0.5 → **물이 이 높이까지 차는 일이 없다**. 월류·붕괴·들판 침수·숲 피해가 모두 발생하지 않음.
- **수정: 스케일 표를 설계서 3장에 신설**하고 모든 높이 수치를 이 표 기준으로 재지정.

  | 항목 | 기준값 (제안) |
  |---|---|
  | 물 1단위 | 셀 1개 × 수심 1.0 |
  | 평상시 수심 | 0.02~0.1 |
  | 위험 수심(기지 피해) | 셀당 ≈ 0.13 (flood 1.2) |
  | 지형 경사 | 기지 0.6 → 가장자리 1.4 |
  | 제방 높이 Rank1/2/3 | 0.3 / 0.4 / 0.5 |
  | 모래주머니 | 0.25 |
  | 닫힌 수문 | 0.8 |
  | 들판 수입 정지 수위 | 0.05 |
  | 숲 피해 수위 | 0.1 |
  | 범람원 개방 | 지면 −0.15 / −0.2 / −0.25 |
  - 구현 첫 단계(T04)에서 프로토타입으로 재검증 후 확정.

## 6. 반영 순서 제안

1. **스케일 표(C6) + 지형 경사(C1) + 증발(C2) + 펌프 상한(C5)** 을 통합 설계서 3장에 반영 → 프로토타입으로 재검증(방어 없음 W2~3 패배, 펌프 1대 단독 클리어 불가).
2. **구역 레이어(C3)** 를 상세 설계서 11장에 반영, 출시 맵 4장 구역 지도 작성.
3. **경험치 예산표(C4)** 확정 → 점수원 계수 조정.
4. 높음 항목(H1~H8) 반영.
5. 중간 항목은 M1·M2·M10을 출시 전 필수, 나머지는 M5 단계.

> 1~3은 구현 첫 단계(T03~T04)에 프로토타입과 함께 진행하는 것이 효율적이다(문서 수치만으로는 또 어긋날 수 있음).
