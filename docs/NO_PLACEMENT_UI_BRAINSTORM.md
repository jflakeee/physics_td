# 배치 UX가 필요 없는 UI — 리서치 & 브레인스토밍

> 작성일: 2026-11-08 · 관련: [모바일 재구현 검토](MOBILE_REBUILD_REVIEW.md), [설계 검토](DESIGN_REVIEW_2026-11.md)
> 문제 정의: 현재 조작의 병목은 **"작은 격자에서 정확한 (x, y)를 고르는 일"** 이다. 이걸 개선하는 대신 **없앤다.**

## 1. 접근 방향 5가지

| # | 전략 | 핵심 질문 |
|---|---|---|
| ① | **좌표 선택 제거** | 설치 위치를 미리 정해 두면? (고정 슬롯·섹터) |
| ② | **부정확해도 되게** | 물리가 알아서 흘러간다면, 대충 그어도 되지 않나? (선 긋기·굴착) |
| ③ | **위치 대신 대상 선택** | "어디에"가 아니라 "무엇에" — 물·수문·방향을 탭 |
| ④ | **배치 자동화** | 플레이어는 정책/예산만, 배치는 시스템이 |
| ⑤ | **다른 입력 수단** | 기울이기, 스와이프 제스처 |

**공통 교훈**
1. 성공한 모바일 TD는 대부분 **좌표 대신 "슬롯/레인/구역"** 을 고르게 한다.
2. 물리 게임은 **부정확한 입력을 물리가 흡수**할 때 재미있다(Where's My Water). 반대로 정밀도를 요구하면 불만(From Dust).
3. 고정 슬롯은 "자유도 감소"가 아니라 **레벨 디자이너의 도구**가 된다(Thronefall).

## 3. 컨셉 브레인스토밍 (12안)

### A. 고정 거점 + 링 메뉴 *(①, Kingdom Rush/Thronefall형)*
```
   ·  ◯  ·  ·  ◯  ·        ◯ = 거점(지대 높은 곳, 6~10개)
   ~~~~~ 물 ~~~~~         거점 탭 → 주변에 원형 메뉴
   ·  ·  [기지]  ·  ◯       [💧펌프][❄냉각][⬆업]
   ◯  ·  ·  ·  ·  ·
```
- 맵마다 거점 위치가 퍼즐. 거점 수 < 필요 수 → "어디를 포기할지" 선택.
- 👍 구현 쉬움, 터치 목표 60px+ / 👎 자유도 낮음, 제방 표현 어려움

### B. 수문 네트워크 운영 *(③, 배치 0)*
```
 [북 유입]
     ║
  ═══╬═══⊟═══ 저류지       ⊟ = 수문 (탭 = 열기/닫기)
     ⊟                     ◉ = 펌프 (탭 = 가동, 전력 소모)
  ══[기지]══⊟══ 강 → 배출
     ◉
```
- 수로·수문·펌프가 **처음부터 깔려 있음**. 플레이어는 실시간으로 열고 닫고 켜고 끈다.
- 철도 신호 퍼즐 + 실시간 운영. "언제 열지" 타이밍 = 깊이.
- 👍 배치 완전 제거, 물리가 주인공, 짧은 세션 / 👎 맵 제작 비용, 리플레이성은 맵 수에 비례

### C. 손가락 굴착·성토 *(②, Where's My Water/From Dust형)*
- 한 손가락 문지르기 = **굴착**(지면↓, 수로), 툴 전환 후 문지르기 = **성토**(지면↑, 제방).
- 브러시 반경 넓게(손가락 크기), 흙 예산 = 자원. 굴착한 흙이 성토 재료(보존).
- 👍 가장 직관적·물리 쇼케이스 최고 / 👎 높이맵 필수, 대충 문지르면 정답이 되어 깊이가 얕을 위험 → **흙 예산·시간 제한**으로 조절

### D. 선 긋기 제방 *(②)*
- 드래그한 궤적이 스무딩되어 제방이 됨. 길이 = 비용, 끝점은 지형에 자동 스냅.
- 제방은 **월류 높이·내구도**를 가짐 → 긴 선 하나 vs 이중 제방 선택.
- 👍 한 획 입력, 직관적 / 👎 선이 시뮬 격자와 정렬되도록 래스터화 필요

### E. 물에 직접 쓰는 스킬 *(③, Water TD/Clash Royale 주문형)*
- 건물 없음. 하단 스킬 카드(쿨다운): **탭한 곳 결빙**(넓은 원), **증발**, **스와이프 방향으로 물 밀기**, **임시 모래주머니 벽(스와이프)**.
- 범위가 넓어 정밀도 불필요. 액션성↑
- 👍 즉각적 재미, 짧은 학습 / 👎 전략 깊이·계획성 약함 → 다른 안의 **보조층**으로 적합

### F. 방향 카드 레인 *(①④, PvZ/Rush Royale형)*
```
        [북 ▲ 슬롯 □□□]
[서 ◀ □□□]  기지  [□□□ ▶ 동]
        [남 ▼ 슬롯 □□□]
  손패: [제방][펌프][냉각][제방]
```
- 각 유입 방향에 방어 슬롯 3칸. 카드를 방향 버튼(화면 가장자리, 큰 목표)에 드래그.
- 지도 좌표 개념 제거, **"어느 방향에 무엇을 몇 개"** 로 추상화.
- 👍 모바일 최적, 덱빌딩·로그라이트 확장 쉬움 / 👎 물리 시뮬의 공간성이 약해짐

### G. 섹터 링 방어 *(①, 원형 레이아웃)*
```
          ╱ N1 ╲ N2 ╲
       W2 │ ┌────┐ │ E1      기지 둘레를 8~12개 섹터로 분할
       W1 │ │기지│ │ E2      섹터 탭 → 제방 높이↑ / 펌프 / 냉각
          ╲ S2 ╱ S1 ╱       바깥에서 물이 안쪽으로 밀려옴
```
- 4방향 홍수 설계와 **자연스럽게 맞는 극좌표 UI**. 섹터 = 거대 터치 목표.
- 섹터 간 물이 옆으로 번짐(약한 섹터로 우회) → 균형 배분 퍼즐.
- 👍 세로 화면에 원형 보드가 꽉 참, 한 손 조작 / 👎 지형 다양성 표현 제한

### H. 자동 배치 + 정책 *(④)*
- 플레이어는 방향별 **예산 슬라이더**와 **전략 성향**(막기/빼기/얼리기)만 설정 → 시스템이 최적 위치에 배치.
- 👍 입력 최소 / 👎 "내가 막았다"는 손맛 상실, AI 품질 의존 → **"자동 배치 제안 + 1탭 수락"** 정도로만 쓰는 게 현실적

### I. 기울이기(자이로) *(⑤)*
- 폰을 기울이면 맵 전체 물이 쏠림(Where's My Water 보너스 레벨). 궁극기/미니게임용.
- 👍 신선함, 물리 체감 최고 / 👎 접근성·데스크톱 불가·앉아서/누워서 플레이 문제 → **보조 이벤트**로만

### J. 파이프 회전 퍼즐 *(③)*
- 수로 타일을 **탭해서 회전**(Pipe Mania형) → 물을 배출구로 연결. 웨이브 중에도 회전 가능.
- 👍 탭 한 번 조작 / 👎 타일 크기 문제 재발 가능 → 타일 수 적은 맵에서만

### K. 시간 정지 계획 → 실행 *(전 단계 보조)*
- 준비 단계에서 "예측 물길"이 미리 그려지고(시뮬 선행 실행), 플레이어는 위험 표시된 곳의 **추천 대응 칩**만 탭.
- 👍 정보 → 결정 흐름이 명확 / 👎 단독 컨셉은 아님

### L. 머지 보드 *(①④)*
- 지도와 분리된 3×5 머지 보드에서 시설 유닛 합성 → 강해진 유닛이 자동으로 담당 방향 배치.
- 👍 모바일 친화, 수익화 친화 / 👎 물리 TD 정체성 희석

## 5. 추천 조합

단일 안보다 **층(layer) 구성**이 강하다:

| 층 | 역할 | 후보 | 입력 |
|---|---|---|---|
| 준비 (웨이브 사이) | 구조 결정 | **G 섹터 링** 또는 **A 고정 거점** | 큰 목표 탭 |
| 운영 (웨이브 중) | 타이밍 결정 | **B 수문·펌프 토글** | 탭 |
| 긴급 (쿨다운) | 손맛·역전 | **E 물 스킬** 2~3개 | 탭/스와이프 (넓은 범위) |

→ **"좌표를 고르는 순간"이 0**인 상태로 계획·운영·액션 세 종류의 결정을 모두 제공.

대안 방향(샌드박스형): **C 굴착·성토 + E 스킬**. 물리 재미는 최고지만 높이맵·브러시 튜닝 비용이 크다. 먼저 최소 프로토타입으로 손맛 확인 후 결정.

## 6. 다음 단계 — 비교 프로토타입 3종 (각 0.5~1일)

| 프로토 | 내용 | 검증 질문 |

| P1 섹터 링 + 수문 | 원형 보드, 8섹터 탭 업그레이드, 수문 4개 토글 | 설명 없이 30초 안에 조작을 이해하는가? 웨이브 중 할 일이 있는가? |

| P3 고정 거점 + 물 스킬 | 거점 8개 링 메뉴, 결빙·밀기 스킬 | 거점 선택이 고민되는가? 스킬이 계획을 무력화하지 않는가? |
